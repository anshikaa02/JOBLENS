# JobLens Backend (Phase 6)

FastAPI service. Currently implements one real feature: PDF resume upload
→ text extraction → rule-based ATS scoring. Job matching (Phase 7), Gemini
AI features (Phase 8), MongoDB (Phase 10), and full auth (Phase 9) come later.

## Setup (do this once)

Requires Python 3.11+ (3.12 confirmed working; if you're on 3.14 and hit a
pydantic-core build error, see the main README's troubleshooting notes).

```bash
cd backend
python -m venv .venv
```

Activate the virtual environment:
- **Windows (PowerShell):** `.venv\Scripts\Activate.ps1`
- **Mac/Linux:** `source .venv/bin/activate`

Then install dependencies:
```bash
pip install -r requirements.txt
```

### Gemini API key (required for Phase 8 — Career AI)

1. Get a free key at https://aistudio.google.com/apikey
2. Copy `.env.example` to `.env` in the `backend/` folder
3. Paste your key in: `GEMINI_API_KEY=your_actual_key_here`
4. `.env` is git-ignored — never commit it

Without this key, every other feature (Resume Analyzer, Job Matcher) still
works fully — only the Career AI page's three features need it, and they'll
return a clear "GEMINI_API_KEY is not set" error instead of crashing if
it's missing.

## Run it

```bash
uvicorn app.main:app --reload --port 8000
```

Leave this running in its own terminal — the frontend's Vite dev server
proxies `/api/*` requests to `http://localhost:8000` automatically (see
`frontend/vite.config.ts`), so **both** the backend (`uvicorn`, port 8000)
and frontend (`npm run dev`, port 5173) need to be running at the same time
for the Resume Analyzer page to work.

Visit `http://localhost:8000/docs` for FastAPI's interactive API docs (Swagger UI) —
useful for testing the `/api/resume/analyze` endpoint directly, without the frontend.

## Structure

```
backend/
  app/
    main.py              FastAPI app, CORS config, route registration
    routers/
      resume.py          POST /api/resume/analyze
    services/
      pdf_parser.py       Extracts text from PDF bytes (pdfplumber)
      ats_scorer.py        Rule-based scoring engine — see file docstring
    schemas/
      resume.py           Pydantic response models
  requirements.txt
```

## Why rule-based scoring, not AI, in this phase

The ATS score is deliberately NOT generated by an LLM. A real Applicant
Tracking System cares about parseable structure and keyword presence —
that's a well-defined, testable problem suited to explicit rules (each
worth a fixed point value, see `ats_scorer.py`'s docstring). Gemini-powered
suggestions and rewrites are a genuinely different problem — subjective,
open-ended text generation — and that's what Phase 8 adds on top of this.
